## Plan: A/B tests without hand-editing: settings file, pick lists, Editor window, cheat overrides, mismatch checks

### Goal
- Setting up and running an A/B test should need no hand-edited JSON or C#.
  - The game's settings live in a settings file (`iec-settings.json`), and the C# that declares them is generated from it.
  - Tests, variants, settings, winners and `forceVariant` are always picked from a list, never typed.
  - Values use a control that matches their type.
- The cheat menu can override each setting for the current session.
- A mismatch between the settings and the catalog is reported:
  - in the Editor,
  - before a push,
  - in the Unity build,
  - in the CI build.
- maze-flow and shiny-loop get all of this in their `main`.

- **No Remote Config.**
- **Existing players are not moved into a new test.** `onlyNewInstalls` stays `true`.

### Design
- **`unity/Assets/_Project/Config/iec-settings.json`:**
  - Format: `{ "settings": [ { "key": "ads.inter_interval", "type": "int", "default": 30 } ] }`.
  - Types are `bool`, `int`, `float` and `string`.
  - It sits outside `Resources/`, so it isn't shipped in the build.
- **`unity/Assets/_Project/Scripts/Runtime/GameSettings.Generated.cs`:**
  - Generated by Node only (`scripts/lib/ab-settings.mjs`), with an auto-generated header.
  - It is a `partial` part of `GameSettings` with one handle per setting. The handle name is the PascalCase of the key: `ads.inter_interval` → `AdsInterInterval`. Two keys that give the same name are an error.
  - It also contains `static partial void DeclareGenerated()`.
  - `GameSettings.cs` becomes `partial`, and `Declare()` calls `DeclareGenerated()` first. Hand-written `Settings.Define` lines for custom types stay allowed below that call.
- **All writes go through Node.**
  - The Editor window calls `ab-tests.mjs` through `NodeRunner`, the same way Set release does. That gives one set of rules and one generator.
- **CLI (`scripts/ab-tests.mjs`):**

  | Command | Notes |
  |---|---|
  | `set [<platform> <version> <AB_yyyyMMdd_vNN>] [--replace]` | |
  | `check` | |
  | `setting list` | |
  | `setting add [<key> <type> <default>]` | |
  | `setting default [<key> <value>]` | |
  | `setting rename [<key> <new>]` | Renames in every test's values and result too. |
  | `setting remove [<key>]` | Refused while any test value or result uses the key. |
  | `value [<test> <variant> <setting> <value>]` | `--clear` removes the value. |
  | `ratio [<test> <variant> <n>]` | |
  | `force [<test> <variant>]` | Sets the catalog's `forceVariant`; `--clear` removes it. |
  | `end [<test>] [--winner <variant>]` | Copies the winner's values into `result`. Refused when the test already has a result. |
  | `generate` | Regenerates the C# file. |

  - **Missing arguments:** in an interactive terminal without `--json`, each one is asked.
    - Things that already exist (platform, test, variant, setting, type, winner) are offered as a numbered list, with marks like "(current)", "(ended)", or the type and default.
    - A bool is asked as yes/no.
    - Only new names, versions and values are typed, and they are checked against the type before saving.
    - A new test defaults to today's date.
  - **Without a terminal:** a missing argument is a usage error (exit 2), so agents and CI never hang.
  - **Writing:** every write runs `validate` and writes nothing when the rules break.
  - **Setting changes:** every setting change regenerates the C# file.
  - **Changing a default:** if a test that has no result uses that key, the change asks for confirmation (or needs `--yes`): "changes the control group of AB_…".
- **`scripts/lib/menu.mjs`:** gets `askChoice(question, options)`, which numbered pick lists use.
  - `iec.bat abtests` lists the actions: check, set release, settings, values, ratios, force variant, end test.
- **Editor window (IEC > A/B tests > Edit tests...):**
  - **Settings tab:** a list of settings with Add, Default, Rename and Remove. Type is a dropdown.
  - **Tests tab:**
    - A test dropdown, newest first, marked current, ended or shipped.
    - A grid: rows are the declared settings (from `Settings.Service.All` after `GameSettings.Declare()`, so hand-declared ones show too), columns are variants.
    - Each cell's control matches the setting's type: toggle, int, float or text. A JSON-object setting uses a text field.
    - Each variant has a ratio field.
    - There is a `forceVariant` dropdown.
    - **End test** with a winner dropdown.
    - **New test / Set release** opens the existing Set release window.
  - **Errors:** a red bar lists the mismatches. **Regenerate** appears when the generated file is out of date.
- **Mismatch checks:**
  - **The checks** (errors unless marked):
    1. A catalog value or result uses a key that isn't in `iec-settings.json` and isn't declared by hand in `GameSettings.cs`. Node finds hand-declared keys by parsing the `Settings.Define("key"` lines.
    2. A value doesn't fit its type. Node checks the types it knows from the JSON file; Unity checks every type.
    3. `GameSettings.Generated.cs` differs from what `iec-settings.json` generates.
    4. A key is declared both in `iec-settings.json` and by hand.
    5. A settings file entry is invalid: bad key, bad type, or a default that doesn't fit the type.
    6. *Warning:* a default changed while an unended test uses the key. This is reported only when the tool makes the change.
  - **Where they run:**
    - **Node:** `validateSettings` in `lib/ab-settings.mjs` is called from:
      - `ab-tests.mjs check`;
      - `check-build-config.mjs` `abTestsProblems`, which covers CI through `sdk-config.mjs`. Problems there are "blocking", so a development build only warns, as today.
    - **Unity:**
      - `AbTestsBuildConfigCheck` also compares `Settings.Service.All` with `iec-settings.json` (key, type, default). That catches checks 3 and 4.
      - A new `[InitializeOnLoad]` editor check runs the same comparison after each recompile, and an `AssetPostprocessor` runs it when either JSON file is imported. Each distinct problem is logged once as a console error, and the window shows it.
